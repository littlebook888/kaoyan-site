开始前，准备好这些

  • GitHub 账号：你已有（littlebook888）。Supabase 也推荐用 GitHub 直接登录，最快。
  • 一个记密码的地方：Supabase 数据库密码只显示一次，丢了只能重置，务必先存好（手机备忘录 / 1Password 都行）。
  • 浏览器：Chrome / Edge / Safari 任意。
  • 两个站的文件：
    • 计时器主站：D:\Agentwork\workbuddy\考研个人网站管理系统\（改 static/js/config.js）
    • 题库站：你 fork 出来的 neike-306-tiku 仓库（改 .env + 后续我接代码）
⚠️ 先说清一个认知（之前提过，再强调）：开源代码 ≠ 题目免费。题库站你能复刻是因为原作者已授权你“网站可随意复刻”。Supabase 只存“你的做题进度/收藏/笔记”，不存原题内容（题目来自原作者，已获授权）。这一步只配后端，不涉及搬题。
1

注册并新建 Supabase 项目

约 3 分钟。这一步创建你的“云数据库”。

1.1 打开官网并用 GitHub 登录

① 浏览器打开 https://supabase.com
② 点右上角 Start your project 或 Sign In
③ 选 Continue with GitHub，授权登录。

📸 截图位：Supabase 首页右上角登录按钮 → 选择 GitHub 登录

1.2 新建项目（New project）

① 登录后进入 Dashboard，点 New project
② 填写：

  • Name：kaoyan-sync（随便起，能认出就行）
  • Database Password：设一个强密码，并立刻抄到备忘录（后面填代码用不到它，但丢失只能重置）
  • Region：选 South Asia (Mumbai) 或 Northeast Asia (Tokyo) —— 离国内最近、直连最快（没有中国区节点）
  • Pricing Plan：务必选 Free（默认就是免费档）
③ 点 Create new project

📸 截图位：New project 表单 → Name / Password / Region / Free 计划
等待 1–2 分钟，Supabase 在后台帮你初始化数据库。进度条走完即可。
2

拿到连接密钥（URL + anon key）

这两个值要分别填进两个站。先复制下来，存到备忘录。

① 在左侧栏最底部点 Settings → 选 API
② 在 Project URL 处复制，形如：https://abcd1234.supabase.co
③ 在 Project API keys 处，复制 anon · public 那一条（很长的 eyJhbGci...）

📸 截图位：Settings → API → Project URL + anon public key
🚫 千万不要复制 service_role secret key！它能绕过所有权限、可删库，只能放在安全的服务器端，绝不能出现在前端网页。我们全程只用一个 anon public key，它本来就是给浏览器用的、安全。
把这两个值存好：
• SUPABASE_URL = https://xxxx.supabase.co
• SUPABASE_ANON_KEY = eyJhbGci...（很长）
3

建数据库表（后端本体，一次性粘贴）

把下面整段 SQL 粘进 Supabase 跑一次，两个站要的所有表就建好了（含权限和实时推送）。

① 左侧栏点 SQL Editor → New query
② 清空示例，把下面代码框里的全部内容粘贴进去
③ 点右上角 Run（或按 Ctrl/Cmd+Enter）
④ 看到绿色成功提示、无报错即可。

📸 截图位：SQL Editor → 粘贴 → Run → 绿色成功

-- ---- 计时器主站：6 张表 ----
create table if not exists active_timer (
  user_id          text primary key,
  mode             text,
  kind             text,
  label            text,
  status           text,
  started_at       bigint,
  duration_sec     integer,
  elapsed_sec      numeric default 0,
  updated_at       bigint,
  tags             text[] default '{}',
  sub_category     text,
  segments         jsonb,
  first_started_at bigint,
  task_id          text,
  note             text
);

create table if not exists study_sessions (
  id            text primary key,
  user_id       text,
  type          text,
  kind          text,
  duration_sec  integer,
  label         text,
  started_at    timestamptz,
  ended_at      timestamptz
);

create table if not exists time_records (
  id              text primary key,
  user_id         text,
  category        text default 'study',
  sub_category    text,
  label           text,
  tags            text[] default '{}',
  started_at      timestamptz,
  ended_at        timestamptz,
  duration_sec    integer,
  source          text,
  block           text,
  note            text,
  task_id         text,
  created_at      timestamptz,
  segments        jsonb
);

create table if not exists tasks (
  id                  text primary key,
  user_id             text,
  title               text,
  done                boolean default false,
  date                text,
  category            text default 'general',
  slot                text,
  block               text,
  subject             text default 'other',
  task_type           text default 'other',
  estimated_min       integer,
  remind_on_estimate  boolean default true,
  total_focus_sec     integer default 0,
  status              text default 'todo',
  time_record_ids     text[] default '{}',
  created_at          timestamptz
);

create table if not exists events (
  id           text primary key,
  user_id      text,
  title        text,
  date         text
);

create table if not exists goals (
  id            text primary key,
  user_id       text,
  name          text,
  target_hours  numeric,
  deadline      text
);

-- ---- 题库站：2 张表（进度 + 收藏）----
create table if not exists tiku_progress (
  id uuid primary key default gen_random_uuid(),
  user_id text not null default 'kaoyan_user_default',
  group_storage_id text not null,
  subject text not null default '',
  selections jsonb not null default '{}'::jsonb,
  submitted boolean not null default false,
  notes text,
  updated_at timestamptz not null default now(),
  unique(user_id, group_storage_id)
);

create table if not exists tiku_favorites (
  id uuid primary key default gen_random_uuid(),
  user_id text not null default 'kaoyan_user_default',
  group_storage_id text not null,
  subject text,
  created_at timestamptz not null default now(),
  unique(user_id, group_storage_id)
);

-- ---- 开启行级安全（单用户演示模式，已放宽）----
alter table active_timer    enable row level security;
alter table time_records    enable row level security;
alter table study_sessions  enable row level security;
alter table tasks           enable row level security;
alter table events          enable row level security;
alter table goals           enable row level security;
alter table tiku_progress   enable row level security;
alter table tiku_favorites  enable row level security;

drop policy if exists "anon_all_active_timer" on active_timer;
create policy "anon_all_active_timer" on active_timer for all using (true) with check (true);
drop policy if exists "anon_all_time_records" on time_records;
create policy "anon_all_time_records" on time_records for all using (true) with check (true);
drop policy if exists "anon_all_study_sessions" on study_sessions;
create policy "anon_all_study_sessions" on study_sessions for all using (true) with check (true);
drop policy if exists "anon_all_tasks" on tasks;
create policy "anon_all_tasks" on tasks for all using (true) with check (true);
drop policy if exists "anon_all_events" on events;
create policy "anon_all_events" on events for all using (true) with check (true);
drop policy if exists "anon_all_goals" on goals;
create policy "anon_all_goals" on goals for all using (true) with check (true);

drop policy if exists "tiku_progress_anon" on tiku_progress;
create policy "tiku_progress_anon" on tiku_progress for all
  using (user_id = 'kaoyan_user_default') with check (user_id = 'kaoyan_user_default');
drop policy if exists "tiku_favorites_anon" on tiku_favorites;
create policy "tiku_favorites_anon" on tiku_favorites for all
  using (user_id = 'kaoyan_user_default') with check (user_id = 'kaoyan_user_default');

-- ---- 开启 Realtime 实时推送（三端同跑同控的关键）----
alter publication supabase_realtime add table active_timer;
alter publication supabase_realtime add table time_records;
alter publication supabase_realtime add table study_sessions;
alter publication supabase_realtime add table tasks;
alter publication supabase_realtime add table events;
alter publication supabase_realtime add table goals;
alter publication supabase_realtime add table tiku_progress;
alter publication supabase_realtime add table tiku_favorites;
验证建表成功：左侧栏点 Table Editor，应能看到这 8 张表：active_timer、time_records、study_sessions、tasks、events、goals、tiku_progress、tiku_favorites。
提示：当前是“单用户演示”权限（任何人用 anon key 都能读写，但我们用固定 user_id 当唯一身份）。等日后要多人共用，再细化 RLS 即可，现在不用管。

配置计时器主站（改 1 个文件）

主站 HTML 已内置 Supabase JS，只需在 config.js 填两个值，跨设备同步就生效。

① 打开文件：考研个人网站管理系统/static/js/config.js
② 找到开头的 SUPABASE_URL 和 SUPABASE_ANON_KEY，把第 1 步拿到的两个值填进去：

  SUPABASE_URL: "https://abcd1234.supabase.co",      // ← 填你的 Project URL
  SUPABASE_ANON_KEY: "eyJhbGciOiJIUzI1NiIs...",    // ← 填你的 anon public key

  // 单用户标识：三端都填同一个固定字符串，即共享同一份数据
  USER_ID: "chenbenzhen",    // ← 改成你自己的固定 ID（手机/电脑/平板一致）
填完即生效，无需改动其他任何代码。三端都用同一个 USER_ID，数据就合并到同一份。
⚠️ 一个待补的小坑（记下，稍后我修）：主站代码里 Store.initSupabase() 目前的入口调用还没接上，意味着“填了 key 但没自动连”。这不影响你先填好配置；等你把 key 给我、或部署后，我补一行初始化调用，同步徽标就会从「本机存储」变成「云端同步中」。

还能顺手改的（可选）

  • EXAM_DATE：改成你的真实考研初试日期（默认占位 2026-12-19）。
  • TIME_BLOCKS：起床/午餐/晚餐/睡觉时间，按你真实作息改（默认 08:00 / 12:00 / 17:30 / 23:40）。
  • DAILY_GOAL_HOURS：每日目标学习时长，默认 8 小时。

配置题库站（fork 仓库）

题库站的“后端”（表）已在第 3 步建好。这里只把密钥喂给前端。代码接入（把 Supabase 接进做题逻辑）由我按《题库复刻执行计划 阶段 2》来做。

5.1 建环境变量文件

① 在你 fork 的 neike-306-tiku 仓库根目录，新建文件 .env
② 写入以下内容（同样是第 1 步拿到的两个值）：

# 题库站前端读取的环境变量（Vite 约定 VITE_ 开头）
VITE_SUPABASE_URL=https://abcd1234.supabase.co
VITE_SUPABASE_ANON_KEY=eyJhbGciOiJIUzI1NiIs...
安全提醒：.env 含 anon key，虽可公开但建议把它加进 .gitignore（或仓库设了 Secrets 就用 Secrets），避免误提交到公开仓库。不过 anon key 本身可暴露，风险很低。

5.2 代码接入（我来做，你不用动）

按已定计划，我会：

  • 装 @supabase/supabase-js，新建 src/supabaseClient.js 读 VITE_SUPABASE_URL/ANON_KEY；
  • 在 App.jsx 现有“写入 localStorage”的地方，追加“防抖 push 到 Supabase”（按 user_id + group_storage_id）；
  • 切科目时从 Supabase “pull 一次”覆盖本地，保证多端一致；
  • 不引入 Supabase Auth，沿用和主站一致的“单用户 anon 模型”。
所以现在你的动作只有：建好 .env 并告诉我仓库已 fork。代码接好、本地 pnpm build:pages 后，题库进度就会和计时器共用同一个 Supabase、天然三端同步。

验证：三端真的同步了

  1. 手机和电脑分别打开同一个线上地址（部署后才有跨设备，本地预览只能同浏览器多标签）。
  2. 计时器站：电脑端点「开始计时」，手机端应实时看到同一计时在跑，且手机端能暂停/停止它（同控）。顶部同步徽标显示「云端同步中」。
  3. 题库站（代码接好后）：手机端做几道题、收藏几题，电脑端刷新即看到同一进度/收藏。
  4. 任一端关机，其他端数据不丢（数据在 Supabase 云上，不在你电脑）。
没看到同步？依次排查：① key 是否填对（URL 别带斜杠结尾、key 完整）；② 第 3 步 SQL 是否成功跑、8 张表都在；③ 主站那个 initSupabase() 调用是否已补（见第 4 步提示）；④ 是否用的同一 USER_ID。

常见坑 & 注意事项

🕐 7 天无流量自动暂停：Supabase 免费项目若连续 7 天没有任何请求，会暂停（不是删数据）。你每天打开网站用一下就不会触发；万一被暂停，Dashboard 点一下「Restore」即可，数据全在。
🌏 区域选亚太：建项目时 Region 选 Mumbai / Tokyo，国内直连最快。建错只能新建项目重来，所以第 1 步就选对。
🔑 两个 key 别混：anon public 可放前端（我们用它）；service_role secret 绝不能放前端，会删库。
👤 单用户模型：当前靠固定 USER_ID 当唯一身份，三端必须一致。日后要多人各看各的，再上 Supabase Auth + 细化 RLS。
💰 费用：Free 档 = $0/月、500MB 数据库、10GB 带宽、5 万月活、2 个项目。你个人用量远低于额度，长期免费。
📜 版权：后端只存“你的做题进度/收藏/笔记”，不存原题；题库内容来自已授权复刻的原作者。发布前记得把原作者水印换成你的品牌。
